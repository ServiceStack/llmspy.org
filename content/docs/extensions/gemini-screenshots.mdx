## File Stores Overview

File Stores act as isolated knowledge bases for your documents, allowing you to organize, index, and query content using Gemini search grounding.

### Managing File Stores

The main File Stores view lists all existing stores along with their total document count and disk size. You can quickly launch a grounded chat session directly from any store or create a new store by entering a name.

<Screenshot src="/img/gemini/gemini-01-filestores.webp" alt="File Stores Overview and Creation" />

- **Store List**: Displays configured stores (e.g. `docs.servicestack.net`, `servicestack.net`) with document counts and storage metrics.
- **Create New Store**: Enter a descriptive store name (such as `react-templates.net`) and click **Create**.
- **Chat Launcher**: Click the chat bubble icon on any store to instantly open a grounded conversation.

---

### Store Dashboard

Opening a File Store presents a dashboard with three main sections: **Explore**, **Import**, and **Assistants**.

<Screenshot src="/img/gemini/gemini-02-filestore.webp" alt="File Store Dashboard" />

- **Explore**: Browse, search, filter, and inspect imported documents and their metadata.
- **Import**: Ingest documents via direct file uploads, local directories, or automated web crawls.
- **Assistants**: Build and configure embeddable website chat widgets grounded in this store's documents.
- **Sync Store**: Synchronize local document records with remote Gemini vector stores to detect and repair discrepancies.
- **Delete Store**: Permanently remove the store, indexed documents, imports, assistants, and conversation histories.

## Ingesting Knowledge

Gemini RAG supports multiple ingestion methods: automated web crawling, folder syncing, and manual file uploads.

### Web Crawling

The **Web crawl** import fetches an entire website or documentation portal, converts HTML pages into clean Markdown, applies regex transforms, and imports them into your store.

#### 1. Configuring the Web Crawl

Specify the crawling boundaries, URL filters, and robot instructions.

<Screenshot src="/img/gemini/gemini-03-import-web-crawl.webp" alt="Web Crawl Configuration" />

- **Start URL**: The entry point URL to start crawling (e.g. `https://react-templates.net`).
- **Import folder**: Destination folder name for the crawled Markdown files.
- **Max pages & Max depth**: Safety limits to bound the crawl depth and total page volume.
- **Include / Exclude paths**: Glob patterns (e.g. `/**` or `/archives/**`) controlling crawled URLs.
- **Crawl directives**: Toggles to respect `robots.txt`, honor `noindex`, follow `nofollow` links, canonicalize URLs, and remove duplicate content.

#### 2. Advanced Crawl Rules

Define granular path rules to control how specific file types or URLs are handled during crawling.

<Screenshot src="/img/gemini/gemini-04-import-web-crawl-config.webp" alt="Web Crawl Advanced Rules" />

- **Path glob**: Match specific URL patterns (e.g. `**/*.json`).
- **Action**: Choose actions such as *Follow links only* to traverse discovered links without indexing the raw payload.

#### 3. Regex Content Transforms

Clean and normalize crawled Markdown content before indexing using regex pattern matching and replacement rules.

<Screenshot src="/img/gemini/gemini-05-import-web-crawl-transforms.webp" alt="Regex Content Transforms Configuration" />

- **File glob**: Target specific Markdown files (e.g. `**/*.md`).
- **Regex pattern & Replacement**: Find and replace patterns using capture groups (e.g. converting `\b0(\d)\b` to `\1.`).
- **Flags**: Support for global (`g`), case-insensitive (`i`), multiline (`m`), and dot-all (`s`) matching.

#### 4. Applying & Saving Transforms

Execute regex transforms across all crawled pages and persist rules to `import.json`.

<Screenshot src="/img/gemini/gemini-06-import-web-crawl-transforms-applied.webp" alt="Regex Transforms Applied and Saved" />

- **Feedback Indicator**: Confirms the number of updated pages and persisted transform configuration.
- **View crawled pages**: Open the interactive page inspector to review transformed documents.
- **Import this folder**: Proceed with importing the processed Markdown folder into Gemini.

#### 5. Inspecting Crawled Markdown Pages

Review the crawled directory structure and preview rendered Markdown files before committing the import.

<Screenshot src="/img/gemini/gemini-07-import-web-crawl-view-pages.webp" alt="Inspecting Crawled Markdown Pages" />

- **File Tree Navigator**: Browse folders and individual Markdown files (`index.md`, `next-rsc.md`, templates, etc.).
- **Live Markdown Preview**: Inspect the exact text and headings that Gemini will index for semantic search.

### Importing Local Folders & Metadata

Index local filesystem folders directly into Gemini RAG with rich metadata tagging.

#### 1. Folder Import Configuration

Select a local directory and configure path filters and recurring import options.

<Screenshot src="/img/gemini/gemini-23-import-folder.webp" alt="Folder Import Configuration" />

- **Folder path**: Local path on disk to index (with folder browser picker).
- **Category root**: Strip common prefix folders from document categories.
- **Include only & Exclude**: Filter files using globs (e.g. `**/*.md`, exclude `**/drafts/**`).
- **Save as recurring import**: Save this configuration for repeated one-click re-indexing.

#### 2. Configuring Import Metadata

Assign multi-dimensional metadata attributes to all documents in the import.

<Screenshot src="/img/gemini/gemini-23-import-folder-metadata-dialog.webp" alt="Import Metadata Configuration Dialog" />

- **Standard Attributes**: Assign `Doc type` (e.g. `reference`), `Status` (`published`), `Product` (`ServiceStack`), and `Locale`.
- **Versions & Tags**: Add comma-separated version tags (`v2, v3`) and topic labels (`react`).
- **Source URL Template**: Generate canonical web URLs dynamically using tokens like `https://react-templates.net/{category}/{pathNoExt}`.
- **Rules by Path**: Define overrides for specific subdirectories.

#### 3. Applied Metadata Badges

Review active metadata tags before running the preview.

<Screenshot src="/img/gemini/gemini-24-import-folder-metadata.webp" alt="Applied Metadata Badges" />

- **Metadata Badges**: Visual tags showing active filters (`Doc type: reference`, `Status: published`, `Product: ServiceStack`, `Tags: react`).
- **Edit metadata**: Reopen the dialog to modify metadata settings anytime.

#### 4. Import Preview & Derived Metadata

Validate how files and URLs will be indexed before uploading.

<Screenshot src="/img/gemini/gemini-25-import-folder-preview.webp" alt="Import Preview and Metadata Verification" />

- **Diff Breakdown**: Detailed stats on discovered, new, changed, unchanged, and removed files.
- **Derived Metadata Samples**: Preview resolved URLs and tag badges for individual files.
- **Import Documents**: Click to begin uploading and indexing documents to Gemini.

#### 5. Document Upload Progress

Monitor real-time document upload and indexing progress.

<Screenshot src="/img/gemini/gemini-26-import-folder-uploading.webp" alt="Document Upload Progress State" />

- **Progress Indicator**: Shows current batch progress (e.g. `Uploading 4/18 documents to Gemini...`).
- **View uploads**: Open the detailed upload log to track individual file completions.

## Website Assistants

Publish document-grounded AI assistants as isolated Shadow DOM widgets embeddable on any website.

### Website Assistants Overview

Manage all assistants associated with the current File Store.

<Screenshot src="/img/gemini/gemini-40-assistants.webp" alt="Website Assistants Overview" />

- **Saved assistants**: List of created assistants with deployment status.
- **New assistant**: Click to open the assistant creation wizard.

---

### Assistant Identity & Prompting

Configure how the assistant presents itself to end users.

<Screenshot src="/img/gemini/gemini-41-assistant-identity.webp" alt="Assistant Identity Configuration" />

- **Internal Name**: Name used internally within the dashboard (e.g. `React Assistant`).
- **Display Title & Description**: Public header title (`Ask our assistant`) and description shown in the chat window.
- **Welcome Message**: Initial greeting sent when the widget opens.
- **Suggested Questions**: Configurable prompt chips allowing visitors to ask common questions with one click.
- **Live Preview**: Interactive preview showing real-time widget behavior.

---

### Assistant Behavior & Safety Controls

Configure the Gemini model, system prompt templates, trigger behaviors, and grounding strictness.

<Screenshot src="/img/gemini/gemini-42-assistant-behavior.webp" alt="Assistant Behavior and Safety Controls" />

- **Gemini Model**: Select the model used for generating responses (or use server default).
- **When to Open**: Choose trigger behavior (`Only when initiated` or automatic popup) with optional keyboard shortcut (`Ctrl/⌘+K`).
- **System Prompt Templates**: Choose specialized templates (e.g. *Developer/API assistant*) or supply custom system instructions.
- **Response Style**: Select tone (*Balanced*, *Precise*, or *Creative*).
- **Grounding Requirements**: Require strictly grounded answers and enable inline source citations.
- **Fallback Message**: Custom response returned when no relevant documentation is found.

---

### Assistant Document Scope

Restrict the assistant's knowledge base to specific subsets of documents using metadata facets.

<Screenshot src="/img/gemini/gemini-43-assistant-document.webp" alt="Assistant Document Scope Configuration" />

- **Category & DocType Filters**: Restrict knowledge to specific categories or document types (e.g. `docType = reference`).
- **Status & Version Filters**: Ensure public widgets only answer using `status = published` and targeted product versions.
- **Server Enforcement**: All scope filters are enforced server-side and cannot be tampered with by the client website.

### Hosting & Access Security

Control CORS origins and set rate limits to protect your assistant against abuse.

<Screenshot src="/img/gemini/gemini-49-assistant-hosting.webp" alt="Hosting and Access Security" />

- **Allowed Origins**: Whitelist host domains (e.g. `https://docs.example.com`, `https://*.example.com`, `http://localhost:5173`). Leave blank to permit any website.

### Deployment & Embed Script

Publish your assistant and copy the embed script snippet to install it on your website.

<Screenshot src="/img/gemini/gemini-50-assistant-publish.webp" alt="Published Assistant and Embed Script" />

- **Embed Snippet**: Copy the generated `<script>` tag into your site's HTML:
  ```html
  <script src="https://localhost:5001/chat/ext/gemini/public/assistants/widget.js?g=s8igUb9gJ3u1YvDxztHzuSX" async></script>
  ```
- **Unpublish**: Temporarily disable public access without losing configuration.
- **Regenerate ID**: Invalidate old embed tokens and issue a fresh public widget ID.
- **Archive / Delete**: Archive the assistant or permanently remove it.
